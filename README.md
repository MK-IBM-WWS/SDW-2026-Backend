# Cloud Tariffs — лабораторная работа №3

Тема: тарифы облачного хостинга.
Go + Gin, PostgreSQL + GORM, MinIO Go SDK v7. 

## Быстрый старт

Из корня проекта, после настройки `.env`:

```bash
docker compose up -d postgres minio adminer
go mod download
go run ./cmd/migrate
docker compose exec -T postgres psql -U cloud_user -d cloud_tariffs < database/seed.sql
go run ./cmd/tariffs
```

Нужны Go 1.25+ и Docker Compose v2. Рабочий сервер использует PostgreSQL.

Интерфейс: `http://localhost:8080/tariffs`. API: `http://localhost:8080/api/tariffs`.

## Бизнес-правила

Текущий пользователь зафиксирован: `currentuser.CreatorID = 1`. Функция `currentuser.Get()` создаёт единственный экземпляр через `sync.Once`; метод `ID()` возвращает его неизменяемый ID. Клиент не может выбирать пользователя через JSON, query, cookie или заголовок. Регистрация и заглушка входа этот ID не меняют.

| Исходное состояние | Операция | Результат |
|---|---|---|
| Нет своего черновика | POST `/api/tariffs` | Новый `черновик` |
| Уже есть свой черновик | POST `/api/tariffs` | 409 |
| Свой `черновик` | PUT `…/publication` | `опубликован`, сервер заполняет `formed_at` |
| Свой `опубликован` | Повторная публикация | 409 |
| Свой `черновик` или `опубликован` | DELETE `…/:id` | `удален` |
| Чужой активный тариф | Публикация или удаление | 403 |
| `удален` | Чтение, публикация, удаление, лайк, получение медиа | 404 |

Вернуть опубликованный или удалённый тариф в черновик нельзя. Публикация и удаление — два разных метода. Редактирование названия, описания, цены и RAM выполняется при публикации. После «Далее» файлы не меняются.

Один черновик обеспечивается частичным UNIQUE-индексом PostgreSQL, а не только предварительной проверкой. Публикация, удаление и лайки используют транзакцию с блокировкой строки. Для пары пользователь–тариф есть уникальный индекс. Повторный `value=1` не увеличивает счётчик; повторный `value=0` безопасен.

Входные DTO содержат только разрешённые поля. Неизвестные поля отклоняются с 400, включая `id`, `tariff_id`, `tariff_status`, `creator_id`, `moderator_id`, даты, `is_moderator`, URL и имена медиа. ID в пути выбирает запись, но не меняет её первичный ключ. Параметр `priceLimit` используется исключительно в серверном запросе к БД.

## Контракт API

Успешный ответ:

```json
{"status":"success","data":{}}
```

Ошибка:

```json
{"status":"fail","message":"Понятное описание ошибки"}
```

Пустой список — `data: []`, отсутствие своего черновика или пустая лента — `data: null`, код 200.
Медиа-методы возвращают содержимое файла, а при ошибке доступа/отсутствии тарифа — JSON.

### Все HTTP-методы

| Метод | URL | Вход | Успешный ответ |
|---|---|---|---|
| GET | `/api/tariffs` | Необязательный `priceLimit`: целое ≥ 0 | 200, массив опубликованных тарифов |
| GET | `/api/tariffs/feed` | Необязательный `after_id`: целое ≥ 0 | 200, одна опубликованная карточка или null |
| GET | `/api/tariffs/draft` | Без id и других параметров | 200, свой черновик или null |
| GET | `/api/tariffs/:id` | Положительный id в пути | 200, опубликованный тариф с создателем |
| POST | `/api/tariffs` | multipart: `tariff_name`, файлы `image`, `video` | 201, новый черновик; `Location: /api/tariffs/draft` |
| PUT | `/api/tariffs/:id/publication` | JSON: название, описание, цена, RAM | 200, опубликованный тариф |
| DELETE | `/api/tariffs/:id` | Без тела и query | 200, `{"deleted":true}` |
| POST | `/api/tariffs/:id/likes` | JSON `{"value":1}` или `{"value":0}` | 200, id, признак лайка и количество |
| GET | `/api/tariffs/:id/image` | id в пути | 200, изображение; Range; 302 на заглушку при отсутствии |
| GET | `/api/tariffs/:id/video` | id в пути | 200/206, видео с Range; 302 на заглушку при отсутствии |
| POST | `/api/users` | JSON `login`, `password` | 201, пользователь без пароля |
| POST | `/api/users/login` | JSON `login`, `password` | 200, явная заглушка (`stub: true`) |
| POST | `/api/users/logout` | Без тела и query | 200, явная заглушка (`stub: true`) |
| GET | `/api/users/:id/tariffs` | id пользователя в пути | 200, пользователь и его опубликованные тарифы |

`priceLimit=1000` означает цену **не выше 1000**, включая 1000; API принимает любой целый предел до 2147483647, а старый слайдер сохраняет свои варианты. Лента без `after_id` возвращает первый опубликованный тариф по ID, с `after_id` — следующий. После последнего возвращается первый. Удалённые записи и черновики пропускаются.

## Таблицы PostgreSQL

### `users`

| Поле | Тип PostgreSQL | NULL | Назначение |
|---|---|---|---|
| `user_id` | bigint, sequence | Нет | PK, генерируется сервером/БД |
| `login` | varchar(50) | Нет | Уникальный логин |
| `password_hash` | varchar(255) | Нет | bcrypt-хеш; исключён из JSON |
| `is_moderator` | boolean | Нет | По умолчанию false; клиент не задаёт |

### `cloud_tariffs`

| Поле | Тип PostgreSQL | NULL | Назначение |
|---|---|---|---|
| `tariff_id` | bigint, sequence | Нет | PK |
| `tariff_name` | varchar(100) | Нет | Название |
| `short_description` | varchar(500) | Нет | Описание; до публикации пустая строка |
| `tariff_status` | varchar(20) | Нет | `черновик`, `опубликован`, `удален`; CHECK |
| `image_url` | varchar(500) | Нет | Имя объекта изображения; пустая строка при отсутствии |
| `video_url` | varchar(500) | Нет | Имя объекта видео; пустая строка при отсутствии |
| `price_per_month` | bigint | Нет | Цена в рублях за месяц; CHECK ≥ 0; у нового черновика 0 |
| `ram_gb` | bigint | Нет | RAM в ГБ; CHECK ≥ 0; публикация требует > 0 |
| `created_at` | timestamptz | Нет | Время создания, устанавливает GORM |
| `creator_id` | bigint | Нет | FK → users.user_id; сервер подставляет singleton ID |
| `formed_at` | timestamptz | Да | Время публикации; до публикации NULL |

Отдельных полей модератора и даты завершения у тарифа в текущей трёхстатусной модели нет. Их нельзя добавить/изменить запросом: неизвестные поля отклоняются. `created_at` тарифов сохранён из исходной модели, поскольку задание ЛР3 прямо относит дату создания к вычисляемым системным полям. В `users` и `user_tariff_likes` дат создания нет.

### `user_tariff_likes`

| Поле | Тип PostgreSQL | NULL | Назначение |
|---|---|---|---|
| `like_id` | bigint, sequence | Нет | PK |
| `user_id` | bigint | Нет | FK → users.user_id |
| `tariff_id` | bigint | Нет | FK → cloud_tariffs.tariff_id |

UNIQUE `(user_id, tariff_id)` исключает повторный лайк. Отмена лайка удаляет строку **связи**; требование soft delete относится к тарифам. При удалении тарифа сама запись, файлы и прежние лайки сохраняются, но API их не выдаёт.

`Creator`, `LikeCount`, `IsOwner`, `IsLiked` — ассоциация/вычисляемые поля Go, отдельных колонок для них нет. `like_count` — COUNT связей, `is_liked` — EXISTS для текущего пользователя, `is_owner` — сравнение creator_id с singleton ID.

### Пользователи

Регистрация: логин 3–50 символов `[a-z0-9_.-]`, приводится к нижнему регистру; пароль 8–72 байта. Пароль хранится как bcrypt-хеш, не возвращается в JSON. Новый пользователь всегда `is_moderator=false`. Повторный логин — 409.

Вход и выход — только заглушки ЛР3. Они не проверяют пароль, не создают и не удаляют реальную сессию, не устанавливают cookie или токен и не меняют текущего пользователя. Ответ явно содержит `stub: true`; у входа также `authenticated: false`. Настоящая авторизация остаётся для ЛР4.

### Медиа и подстановка по умолчанию

Если имя пустое, объект отсутствует или MinIO временно недоступен, используются **локальные** `/static/media/example.jpg` и `/static/media/example.mp4`. При пустом имени API сразу возвращает эти адреса в `image_url`/`video_url`; при отсутствующем объекте медиа-метод перенаправляет на соответствующий статический адрес (302). Эти файлы не берутся из MinIO. Название отсутствующего объекта в БД не заменяется на имя заглушки. Для удалённого тарифа медиа-метод возвращает 404 после проверки видимости. В сохранённых HTML-страницах `media-fallback.js` также обрабатывает ошибку загрузки изображения или воспроизведения видео: заменяет `src` на соответствующий статический адрес. Повторная ошибка самой заглушки не вызывает цикл. Будущему SPA нужно реализовать такую же обработку `error`: JSON API не может определить, способен ли браузер декодировать полученный файл.
